# Assumptions and decisions

Format: date · decision · why · how to undo

- 2026-10-02 · Native SwiftUI app built with Swift Package Manager (no Xcode installed) · best Mac feel, no dependencies · switch to Xcode project later if Xcode is installed
- 2026-10-02 · SQLite (system library) instead of SwiftData · SwiftData macros are missing from Command Line Tools · none needed
- 2026-10-02 · Target macOS 26 only · it is the owner's Mac (26.3); allows Liquid Glass · lower `platforms` in Package.swift
- 2026-10-02 · Local wall-clock times, no time zones · single-device personal app · add a TZ column later
- 2026-10-02 · App name "Grove", bundle id `local.grove.app` · placeholder · edit PLAN.md §0
- 2026-10-02 · Four themes: Grove (natural, default), Minimal, Futuristic, Vintage · owner asked for natural + 3 named themes · —
- 2026-10-02 · Desktop icon = symlink `~/Desktop/Grove` → `~/Applications/Grove.app` · no permission prompts needed · delete the symlink
- 2026-10-02 · Day Planner is the top priority feature (owner said so) · built in milestone M2 · —
- 2026-10-02 · Apple/Google Calendar sync is out of scope for v1 · touches data outside the app; needs owner OK · —
- 2026-10-02 · Default layout B (Day Spread) · shows planner, tasks and notes together · edit PLAN.md §0
- 2026-10-02 · Task model is named `TaskItem` · Swift already has a `Task` type · rename in Model/Task.swift
- 2026-10-02 · Saves use upsert (`ON CONFLICT DO UPDATE`), not `INSERT OR REPLACE` · REPLACE deletes the row first and would wipe subtasks and blocks by cascade · none needed
- 2026-10-02 · Daily backup: `VACUUM INTO` a `grove-YYYY-MM-DD.sqlite` copy, keep newest 14 · cheap safety net for local data · change `keep` in Backup.runDaily
- 2026-10-02 · Added test target `GroveTests` (depends on `Grove`) in Package.swift · lets us unit-test AppStore planner logic (create, move, ripple, undo) without a UI · remove the target; the tests in Tests/GroveTests go with it
- 2026-10-02 · Undo is an own stack of before/after snapshots (`Mutation` in AppStore), not `NSUndoManager` · one undo step can touch tasks and blocks together, and it is unit-testable · M5 must make ⌘Z go to the text editor when a note has focus
- 2026-10-02 · Planner view settings (zoom, snap, work hours, day/3-day/week, tray open) live in UserDefaults via `@AppStorage`, not the `settings` table · they are per-Mac view prefs, no need to export them · move to SettingsRepo
- 2026-10-02 · Release over the tray unschedules task blocks only; plain events are never deleted by a tray drop · avoids silent event loss · —
- 2026-10-02 · Not yet built in the planner (planned later): "only this / all events" dialog for repeats (M4), "Open/create linked note" menu item (M6), Focus mode (M8), drag block onto Week strip / Month day (M4) · they need features that do not exist yet · —
- 2026-10-02 · "Today" button shortcut is ⇧⌘T; ⌘T inside the grid also jumps to now · ⌘T alone is taken by the system tab command · change in PlannerView
- 2026-10-02 · Busy-day alert: planned time = minutes covered by any block (overlaps count once); alert fires once when a change takes a day from ≤ 9h to > 9h; limit read from UserDefaults `planner.dailyLimitMin` (default 540) · owner asked to be alerted past 9 hours · Settings screen in M8 should expose the limit
- 2026-10-02 · Planner content starts 34pt below the window top so the window buttons (hidden title bar) never cover the sidebar toggle · owner reported the left sidebar "does not come out fully" (this was a guess; the real cause is in the next line, the 34pt stays as a safe gap) · change `.padding(.top, 34)` in PlannerView
- 2026-10-02 · Planner grid layers are drawn in an `.overlay` on a plain `Color.clear` base, and the week-day header row has a fixed height (`.fixedSize(vertical:)`, spacer `height: 0`) · the layers had fixed widths from a saved `gridWidth` that only grew, so after the tray closed and reopened the grid stayed wide and pushed the tray off the left edge; the spacer `Color.clear` in the header row had no height limit and made the week-day row about 550pt tall · owner reported both · covered by `PlannerLayoutTests` · revert the two edits in PlannerGrid.swift and PlannerView.swift
- 2026-10-02 · Owner asked for referenceable tasks and a richer task body (bullets, text styling, images). PLAN §5.2, §5.5, §4.1, §13, §15 updated; §15 no longer bans images · owner request overrides the old out-of-scope line · revert the PLAN edits
- 2026-10-02 · Mention text is `[[Title]]`, stored as `[[Title|ID]]`; resolve by ID first, then exact title (case-insensitive); links table is filled by ID; renaming a task rewrites `[[Old|ID]]` in linking bodies · titles change, IDs do not, so mentions survive renames · drop the `|ID` part and resolve by title only
- 2026-10-02 · Images are stored as BLOBs in a new `attachments` table (migration 2), downscaled to 1600 px, referenced as `![alt](grove-image:ID)`, orphans deleted on save · the daily `VACUUM INTO` backup and export then cover images with no extra code · move to files under Application Support if the database gets too big
- 2026-10-02 · One shared `RichTextEditor` (NSTextView + `MarkdownStyler`) for the task body and notes · one place to get lists, mentions and images right · —
- 2026-10-02 · Quick add: if nothing is left for the title after parsing, the whole input stays as the title and nothing is applied; a time on a week/someday task is left in the title (a block needs a day) · avoids empty titles and orphan blocks · edit QuickAddParser
- 2026-10-02 · A small "next date" function for repeating tasks is built in M3 and moves into `RecurrenceEngine` in M4 · M3 needs repeats on completion but the full engine comes with the calendar · replace the call in AppStore
- 2026-10-02 · A mention only carries an id when it is a UUID (`[[Title|UUID]]`); `[[Yes|No]]` is just a title with a bar in it · lets titles use `|` and stops a stray word being read as an id · loosen `ReferenceParser.idRegex` if ids stop being UUIDs
- 2026-10-02 · With an id, a mention resolves by that id only: if the target is deleted it stays dangling (shown struck through) and never jumps to another item with the same title · stops a link silently pointing at the wrong thing · allow title fallback in `ReferenceIndexer.resolve`
- 2026-10-02 · Hand-typed `[[Title]]` ties go note → task → event; among tasks, open before done, then newest · notes are the classic link target; autocomplete (M3d) always inserts the id form, so ties only matter for typed text · reorder in `ReferenceIndexer.resolve`
- 2026-10-02 · `canonicalize` rewrites a resolved mention to the target's current title and id, and a rename rewrites linking bodies directly in SQL without changing their "last edited" time · a rename must not reshuffle the notes list · use `NoteRepo.save` in `ReferenceIndexer.renamed`
- 2026-10-02 · Migration 2 also adds triggers that delete `links` rows when a task, note or event is deleted (cascaded subtasks included) · the links table has no foreign keys, so deleted items left dead links · drop the three `links_cleanup_*` triggers in a new migration
- 2026-10-02 · Orphan images are swept by `AttachmentRepo.sweepOrphans` (called at launch in M3d), not on every save, and only when older than 24 h · a picture pasted a moment ago has no saved text yet, and undo can bring an image back · change `olderThanMinutes`
- 2026-10-02 · The image type is named `StoredImage` (Swift Testing already has a type called `Attachment`) · avoids a name clash in tests · rename
- 2026-10-02 · Images: PNG/JPEG up to 1600 px are stored byte for byte; bigger ones, and other formats (HEIC, TIFF, GIF), are re-encoded (PNG if transparent, else JPEG 0.85); animated GIFs keep only the first frame · keeps the database small · edit `ImageTools.prepare`
- 2026-10-02 · Search indexes the words of a body, not ids or markup (`ReferenceParser.searchText`) · otherwise a search for "3f" would hit every body that has a UUID · call raw body again in the three `search.upsert` calls
