## Golden pictures

16 files in `app/test/ui/goldens/`. Each theme (Grove, Minimal, Futuristic, Vintage) has 4:

- `desktop_<theme>_light.png`, `desktop_<theme>_dark.png`: 1100×620, the Planner with the Tasks panel open. Shows the top strip, the dock, the switch, the left panel and a screen.
- `phone_<theme>_light.png`, `phone_<theme>_dark.png`: 390×844, Today. Shows the top strip and the bar at the bottom.

The pictures show the parts of each theme: Grove soft shadow and blobs, Minimal hairlines, Futuristic glass blur + glow + grid, Vintage paper + hard shadow + dashed chip.

The same 16 files are compared in every CI job. "All 4" in this milestone means the 4 CI jobs:

| CI job | Where the golden tests run |
|---|---|
| Android | Linux |
| Windows | Windows |
| macOS | macOS |
| iOS | macOS |

How the pictures stay the same on each system (`app/test/ui/support.dart`):
- Motion is off, so the background does not move.
- Text uses the Flutter test font. Each letter is a box. Real fonts differ on each system.
- Icons use the icon font of the Flutter SDK (`loadIconFont`).
- Shadows are real (`withRealShadows`).
- `TolerantGoldenComparator` counts a pixel as different when a channel is off by more than 12 of 255 and the pixel is not on a soft edge. At most 0.2 % of the pixels can be different.

### What differs between the systems

The first CI run (38048214818) failed on Linux and Windows: the 8 phone pictures were over the first limit (0.5 % of the pixels, no edge rule). The next run (38048527089) kept the failed pictures (`golden-failures-android`, `golden-failures-windows`). I compared them with the golden files:

| | Pixels off by more than 12/255 | Of these, not on a soft edge |
|---|---|---|
| Linux, 8 phone pictures | 0.709–0.858 % | 0.003–0.060 % |
| Windows, 8 phone pictures | 0.683–0.814 % | 0.002–0.054 % |

All the differences are on icons and on the text boxes. Linux and Windows draw these edges a little softer than macOS. Nothing moved, no colour changed. The most is in Futuristic light (blur and glow).

So the compare got the edge rule, and the limit went down from 0.5 % to 0.2 %. Tests in `shell_golden_test.dart`: a softer edge passes; a thin line that is missing fails; a shape that moved by 3 pixels fails.

A CI job that fails now uploads its pictures (`golden-failures-<target>`, kept 7 days).

To make the pictures again: `cd app && flutter test --update-goldens test/ui/goldens`. Look at each picture before you commit it.

## Phone vs desktop

- Narrower than 700 pt: phone. The 5 screens are a bar at the bottom. The open left panel fills the screen. Buttons are 44×40 pt.
- 700 pt and wider: desktop. A 34 pt strip at the top has the dock, the switch and the appearance button. The left panel is 320 pt wide beside the screen.
- The switch shows text from 960 pt. Below that it shows pictures with a tooltip.

## Notes

- The golden tests do not run on a real phone or tablet. `flutter test` has no device. A run on real devices is F12.
- The golden pictures do not show real letters. The fonts are checked by name in `grove_theme_test.dart`. Each system uses its own fonts; Q-1 in `docs/questions.md` asks if we put font files in the app.
- Nothing is saved yet. Theme, light/dark, motion and the open left panel start fresh on each launch. The F5 store saves them (request in `docs/tracks.md`).
- Screens and panels show a stand-in ("This screen is not built yet."). F7–F10 put the real ones in with `screenBuilder` and `paneBuilder`.
- Not in F6: the settings gear, the command palette button, the hidden title bar, the minimum window size, animation on screen and panel change, Tab focus on the shell buttons. See `docs/assumptions.md` (Track B).
- The macOS app cannot be built on this Mac (no Xcode). The CI builds it.
